FROM SOURCE TO LOCAL

A small setup.
A clear starting point.

Node.js 24 and npm are all you need to build and test. Start without credentials, then connect a dedicated bot when you're ready.

Read the Telegram setup guide ↗
01 — BUILD & VERIFY
git clone https://github.com/vladimirperepelytsia/tg2codexMCP.git
cd tg2codexMCP
npm ci
npm run check
No bot token needed for these checks.
02

Choose what the bot can see.

Copy .env.example to a private .env. Set your bot token, an absolute database path and ALLOWED_CHAT_IDS=<tg_channel_id>. Replace the placeholder with a real numeric Telegram chat ID. Keep sending disabled.

03

Connect your client.

Use an example configuration with absolute paths. Use one stdio client per bot, or share one HTTP service across clients. Polling starts when the process starts.

Already using the bot elsewhere? Polling acknowledges updates and can conflict with another consumer. Existing webhooks are never changed automatically.

Explore the security model ↗

Only the chats you allow

Disallowed chat content is discarded before retention. This is bot access, not personal-account access or a complete Telegram history.

Local retention, deliberate sharing

Messages live in your SQLite database, with seven-day retention by default. Retrieved content is shared with your chosen AI client and is subject to its data policies.

Data stays data

Messages are treated as untrusted content. No shell execution, automatic forwarding or built-in model calls. Keep your client's tool approvals enabled.

Optional means optional

Dot Events is a separate, disabled-by-default extension. Standard tools work without it. Public hosting, OAuth and generic conversation wake-ups remain future work.
